## Notes

1. Fixed-form evidence (physical column 6 is `!` on every continuation record, so
   the statements are executable): `WATFLOW.FOR:44-46` continues the complete
   `if(iDualPor.gt.0)` of `43`, so `call DualPor` is live for `iDualPor > 0`;
   `WATFLOW.FOR:1071` continues `if(i.ge.2)` of `1070`, so the `WTransf`
   accumulation is live. Inside `DualPor` the complete set of continuation records
   is `1028-1029` (`subroutine`), `1032` (`dimension`), `1042` (`DeltaTh=`), `1055`
   (the `i.eq.N` `if`) and `1071` (`WTransf`); no record in `1027-1075` has a
   comment marker in column 1, and `1025`/`1077` are column-1 `*` banners outside
   the routine.
2. Precision: `DualPor` has no `implicit` statement, so `SeIm`, `Se`, `DeltaTh`,
   `TrMaxIm`, `h`, `CondM`, `CondF`, `Par`, `dt`, `hCritA`, `WTransf` and every
   array are default REAL (`f32`/`DefaultReal`). Only `FH`/`FK` compute in double
   (`implicit double precision(A-H,O-Z)`, `MATERIAL.FOR:4`, `350`) on `real h,Par(10)`
   / `real Qe,Par(10)` arguments and return `sngl(...)`, which the port reproduces
   as `as f32`. WATFLOW's own `double precision` list (`21`) excludes
   `hCritA`/`WTransf`.
3. Caller order (`WATFLOW.FOR`): `DualPor` runs once per `WatFlow` invocation at
   `43-46`, before `Iter=0` (`50`); both retry labels (`11 continue` `48`,
   `12 continue` `60`) sit *after* the call, and the non-convergence retries
   (`goto 12` `130`, `goto 11` `149`) therefore never re-run it. It reads `ThOld`
   (never `ThNew`), writes `ThNewIm`, and `ThOldIm(i)=ThNewIm(i)` happens only in
   `Update` (`1112`) under `lWat`. The same step then consumes `SinkIm` at
   `223`/`255`/`286`/`402`, `Solute`/`NEquil` at `1095-1102`, `MassTran` at
   `1353-1360` (both already ported, `accounting.rs:119-128`), and `OUTPUT.FOR:81`
   accumulates `CumQ(11) += WTransf*dt`.
4. Sign convention (not reinterpreted): positive `SinkIm` = mobile to immobile
   (`ThNewIm = ThOldIm + SinkIm*dt` grows), and the consumers multiply positive
   `SinkIm` by `Conc` and negative by `Sorb`. `1063` uses `-(ths-ThOld)/dt` as the
   release bound, which is the source literal (it is not `thr`); `1054-1055` uses
   `.lt.` against `-0.001*hCritA` / `-0.01*hCritA`, also literal.
5. `iModel` is always 0 whenever `iDualPor > 0`: `INPUT.FOR:617-624` sets
   `iModel=0, iDualPor=1` for water model 6 and `iModel=0, iDualPor=2` for model 7,
   before the `ParD` read loop, and `INPUT.FOR:1686` defaults `iDualPor=0`.
   `iDualPor` is assigned nowhere else in `src_reference/*.FOR`. So `FH`/`FK` are
   only ever reached with `iModel=0`, and the kernel rejects any other value as
   unreachable through the audited reader instead of porting the unused models; the
   adapter adds the matching cross-field rejection for a bundle that names the deck
   model (6 or 7) as `iModel`.
6. `thr`/`ths` are derived, not free primitives. `GenMat` is defined inside the
   reader's own file at `src_reference/INPUT.FOR:762` - there is no `GENMAT.FOR` -
   and runs at `HYDRUS.FOR:219`. It assigns `thr(M)=Par(1,M)` and `ths(M)=Par(2,M)`
   at `INPUT.FOR:796-797`, identically in the table branch at `816-817`. The branch
   the active reader takes is the analytic one under `if(iModel.lt.nTabMod)`
   (`INPUT.FOR:791`): `iDualPor` is set only for water models 6 and 7, which are
   remapped to `iModel=0` (`INPUT.FOR:619-624`), and `nTabMod=10`
   (`INPUT.FOR:1685`). `DualPorMaterial` therefore carries no caller-supplied
   `thr`/`ths`; the mobile pair `ParD(1,M)`/`ParD(2,M)` is the single spelling and
   the kernel derives the pair from it (a second, independent spelling could
   contradict the column, and the adapter rejects a `thr` key).
7. `FH`'s third argument is an array. `FH(iModel,Qe,Par)` declares `real Par(10)`
   (`MATERIAL.FOR:350`), so the element-associated actual argument `ParD(7,M)` of
   `WATFLOW.FOR:1044` aliases `Par(1..5) = ParD(7..11,M)`; `FH` gets **no** explicit
   `Par()` shuffle, unlike `FK` at `WATFLOW.FOR:1045-1052`, whose local `Par(1..6)`
   are `ParD(7),(8),(9),(10),(11),(6)`. The `iModel=0` path of `FH` reads
   `Par(1..4)` (`MATERIAL.FOR:356-359`), i.e. `ParD(7),(8),(9),(10)` only.
