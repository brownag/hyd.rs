## Notes
- Item B (resolved from source): `WATFLOW.FOR:294` is `PT=PT-rTop`, with PT the row rhs and ST/RT the row; the Rust Neumann adds `flux` to rhs (`hydraulics/boundary.rs:58-62`). So Rust upper flux (positive in) = -rTop. Lower: `PB=...+rBot` (`:221-222`), so lower flux = +rBot, matching `lower_boundary.rs:17`.
- Item D (resolved): `transform_boundary_row` Neumann does `rhs: row.rhs + flux` once (`boundary.rs:58-62`) and checks diagonal pivot. Builders therefore must exclude rBot/rTop. Also it requires lower.lower==0 / upper.upper==0 (`boundary.rs:~100-112`); builders set these to 0.0.
- Geometric (item A): `WATFLOW.FOR:203`/`:274` apply `lGeom` to liquid Con only; vapor `ConVh` is added arithmetically afterwards (`:211`, `:277`). Gravity B uses liquid ConB (`:205`, `:276`). Rust mirrors `FaceAveraging` at `lower_boundary.rs:221-222`; reuse `crate::hydraulics::FaceAveraging`.
- Sign asymmetry: lower rhs has `+B` (`:221`), upper `-B` (`:285`); thermal term sign flips (`:228` vs `:291`). Existing interior builder is `water.rs:110-137`, arithmetic only; interior unchanged.
- Interior `assemble_water_rows` stays arithmetic and unchanged; `VaporWaterRowsInput` is NOT given a new field (it would break `tests/vapor_water_rows.rs` struct literals); averaging is a builder parameter instead.
- `solve_vapor_water_trial` is `pub(crate)` with `allow(dead_code)`, called by `heat/vapor/driver.rs`; changing its signature would touch an out-of-scope file, hence the local `None` gate. `ClosedFlux` type itself is defined in 29.2.2 (`mod.rs`, out of scope).
- Risk: the `None` local is dead code on the `Some` arm; clippy may flag it (`manual_map`-style/`unnecessary` lints). If so, I will use a `const`-free helper fn returning `None` annotated with a justification rather than `allow` sprawl.
- Dropped terms asserted off in 29.2.2 (lDensity, iDualPor, lWTDep, Rate, fRE=1).
