## Accepted APIs and output policy

- `Lifecycle(cases_path, output_root)` provides `dry_run`, `execute(exact_ids, activation)` and read-only `verify`. An activation has exactly `cases_sha256`, `phase`, `launch_ids`, `kind`, `authorization`; IDs follow CASES order. Full source/compiler/executable provenance, shared phase accounting and bounded process handling are already implemented.
- `bridge.write_report`, `verify_report` and `require_bridges` provide retained-original comparisons and mandatory distinct passing reports. A valid numerical bridge difference is preserved as a failed comparison, not hidden as a parser failure. Bridge-only work needs no independent analytical reference.
- `ReferenceCache(root).reference(..., allow_work=False, allow_escalation=False)` returns reference, diagnostics (or None), admission. Exact identity includes case, coordinates, both full schedules, settings/runtime and evaluator provenance. Read-only finite-cache reuse reconstructs diagnostics/admission from authenticated completed stages; it performs no inversion or new component evaluation.
- Cache root defaults to `<output-root>/reference-cache` so paired solver/dt rows share only genuinely identical requests. Missing references are explicitly missing; `unmet` admission stays scientific unmet. Optional escalation is disabled unless separately explicit in the command and recorded authorization; no automatic extra order is introduced.
- Fresh actions create unique batch directories below the required output root. Planned manifests are never converted into attempted runs. `--batch PATH` limits read-only verification to one batch; absent it, verification enumerates all recorded batches rather than silently picking the latest. `--resume-batch PATH` is execute-only and must reproduce the original recipe/activation identity.
- Resume does not fabricate a new authorization: original activation bytes/hash remain immutable, and a narrowed lifecycle activation is an explicitly documented subset of the original IDs carrying the same authorization reference. A row with any incomplete/failed start cannot be reissued. Missing metrics/report receipts may be produced from independently verified completed solver evidence; conflicting existing output blocks instead of being overwritten.
- Completion of this tool is distinct from reference admission, bridge parity, mathematical accuracy and M5-V closure. Proposed exits are 0 for a successful requested tooling operation, 1 for a recorded scientific unmet/failure outcome, and 2 for invalid/incomplete/tampered operational inputs; recipe-only verification makes no scientific acceptance claim.
