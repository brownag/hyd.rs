# Task 4.1.1 micro-plan — Add validated Mesh1D and profile conversion

## Goal

Add a filesystem-free, validated `Mesh1D` contract that converts source-style one-based profile indices into zero-based Rust indices with typed failures.

## Steps

1. Confirm the existing `hydrus-core` public exports, `HydraulicError` conventions, and permitted-file boundary before implementation.
2. Define the `Mesh1D` representation in `crates/hydrus-core/src/hydraulics/types.rs`, carrying finite strictly increasing coordinates, zero-based material indices, optional zero-based layer indices, declared material/layer counts, and a finite inclination cosine/metric.
3. Add typed mesh validation errors to `crates/hydrus-core/src/error.rs` only where the existing error variants cannot distinguish non-finite, length, ordering, count, index, or inclination failures.
4. Implement validated native construction for already zero-based mesh data, rejecting empty/mismatched or otherwise invalid profile inputs without solver or filesystem dependencies.
5. Implement an explicitly named source-adapter constructor accepting one-based material/layer indices, rejecting zero and out-of-range values before converting successful inputs to zero-based storage.
6. Expose only the mesh accessors and module/root exports required by later geometry and stencil tasks; do not add coefficient, boundary, solver, or geometry calculations.
7. Add `crates/hydrus-core/tests/mesh_contract.rs` covering successful one-based conversion, zero-based internal indices, optional layers, declared counts, coordinates, and inclination/metric access.
8. Extend the contract tests for non-finite values, non-increasing coordinates, coordinate/index length mismatches, zero source indices, out-of-range material/layer indices, invalid declared counts, and invalid inclination/metric values, asserting typed errors.
9. Run `cargo test -p hydrus-core --test mesh_contract`, `cargo fmt --check`, and `cargo clippy -p hydrus-core --all-targets -- -D warnings`; inspect that no filesystem or solver dependency was introduced.
10. Record the accepted task report and exact verification results in `STATE_4.md` only after the orchestrator accepts the implementation; preserve all source/reference and planning master files.
