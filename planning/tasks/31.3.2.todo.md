## Notes
Fortran switching order (one iteration of the Picard loop, `src_reference/WATFLOW.FOR`):
1. `Shift` called at WATFLOW.FOR:86, before `Gauss`, using the previous iterate hNew/Con/ThNew.
   Active only if TopInf and (|KodTop|=4 or |KodTop|=1 and rTop>0) (WATFLOW.FOR:393-394).
   - KodTop>0 (head mode): vTop = Darcy + storage + sink + vapor terms ConVh*dh/dx + ConVT*dT/dx
     (:395-407). If |vTop|>|rTop| or vTop*rTop<=0 and |KodTop|=4 => KodTop=-4 (:408-410).
     Then if KodTop=4 and hNew(N) <= 0.99*hCritA and rTop<0 => KodTop=-4 (:411-412).
   - KodTop<0 (flux mode): if not WLayer and hNew(N)>0 => KodTop=+4, hTop=0 (:414-419); then if
     hNew(N)<=hCritA => KodTop=+4, hTop=hCritA (:421-425).
2. `Gauss` solve (:93); then clamp hNew(NumNP)<hCritA => hCritA, and nodes >90% depth when Sink<=0 (:97-100).
3. WLayer only: hNew(N)>hCritS => KodTop=4,hTop=hCritS (:158-161); not used in the met deck (WLayer false).
4. On non-convergence: KodTop=KTOld (:142). SetBC (TIME.FOR:112-147) sets hCritA=-abs(hCA) (:120);
   lMeteo: rTop=-abs(Prec) (:130-131); rain after dry (rTop>0, rTopOld<0, no WLayer) resets KodTop=-4,
   hTopN=-0.01*xConv when KodTop=4 or hTopN>xLimit (:133-141). hCritA only applies when TopInF (INPUT.FOR:104).
   KodTop=-4 init (INPUT.FOR:106-108). Pinned run: -4->4 at 42.7 h, 4->-4 at 120.1 h, -4->4 at 200.3 h.

Differs from existing Rust `select_mode` (post-solve, demand sign based); the vapor path must NOT reuse it.

PARITY RISK (D-10 stop condition): Fortran re-evaluates Shift every Picard iteration (<=2 per step) and
continues iteration 2 from iterate 1 with the new KodTop. `solve_vapor_water_trial` holds the upper pair fixed
for its entire internal Picard loop, and water_solver.rs/vapor/mod.rs are read-only. My decomposition re-solves
the whole step on a switch, which can differ from Fortran by one iteration of history. I cannot prove parity
before 31.4.1; I will implement the step-level decomposition, and report (not work around) if tests expose it.
