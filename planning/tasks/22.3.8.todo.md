## Notes
Reproduction: from the 22.4.1 evidence (`M5V_STUDY_22_REACTIONS.md`): S1 first-order error 6.2e-4..2.5e-3, S2 and S3 error exactly 1.00 relative (=0) at all times, reaction_zero exact. Root cause (read from code, per the Fortran slot semantics):
- The kernel reads the chain production for species js from the PARENT's slots, not the daughter's: `driver.rs:1051-1070` sets `pj=(js-1)*16` and `gam_l1p = p(pj+14)*pf.gam_l1p`, `gam_s1p = p(pj+15)*...`; `processes.rs:571-573` (`chain_source`) forms `cG = c_prev*(gam_l1p*th_w + ro*frac*f_em*xks_p*gam_s1p*sconc_p + ...)`. So `gam_l1/gam_s1` of species j is "the decay of j that produces j+1".
- The same slots also act as an own-species sink: `processes.rs:697` `base = -(gam_l + gam_l1)*th_w` (and the `gam_s + gam_s1` sorbed counterpart, `processes.rs:325`). Hence `gam_l` = decay with no product, `gam_l1` = decay with product; their sum is the total decay.
- 22.3.5 fix C wrote the parent's rate into the DAUGHTER's `offset+13/14` (`solute.rs:1138-1142`). The kernel reads parent slots (species 0 `offset+13/14` = 0), so `chain_source` gets `gam_l1p = gam_s1p = 0`: no production, S2/S3 stay at 0. Side effect: the daughters also get an extra sink of the parent's rate via `gam_l1`, and every species gets its own rate in `gam_l` (`solute.rs:1134-1135`) so no species with a daughter is double counted only because `gam_l1` was empty on the parent.
- Not the cause: `c_prev` wiring (`driver.rs:1197-1201`, `c_prev_o` updated `:1817`) and `chain_noneq=false`. Reachability (ADR 0007/0010): selectors fixed by the public path (equilibrium/linear, no dual porosity, no bacteria `bact`, `lVapor`/`lWTDep` off); `chain_source` equilibrium branch is the one used.
Fix mapping chosen: has-daughter species put the full decay in `gam_l1/gam_s1` and 0 in `gam_l/gam_s`; the last species keeps it in `gam_l/gam_s`. Total sink equals the FV decay on total mass for every species; the daughter source equals parent decay times parent total mass (FV `solute.rs:1664-1670`).
