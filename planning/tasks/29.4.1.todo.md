### Cause hypothesis (physics, not yet proven)
At h=-1e4 cm the retention capacity C=dtheta/dh is tiny (my estimate from the van Genuchten row Alfa .015, n 1.875: about 4e-7 /cm; ~70x larger at -1e3 cm). In the dry deck the end nodes are Dirichlet, so any vapor/thermal flux imbalance is absorbed by the boundary. In the closed pair the top node has no head constraint, and the thermal-vapor flux from the 45->5 C gradient (about 2e-5 cm/h, vTop observed) acts on a node with nearly no storage, so h moves thousands of cm in one step (dh ~ q*dt/(C*dz)), leaves the hTab span (hTab 1e-4..100, `SELECTOR.IN:25`), overshoots, and Picard iteration (MaxIt 20) cannot converge. The dt cuts never help because the failure is already in step 1 (hTop -1.35e4 at dt 0.1) and dtMin is only 0.01. The initial step size therefore contributes but is not the root cause; low storage at boundary nodes with flux BC is.

### Candidate variants (each one change to the closed_flux_on deck)
- A (wetter start, more storage): PROFILE.DAT column 3 `-10000.000` -> `-1000.000` for all 41 nodes. Expect larger C so boundary head moves hundreds, not thousands of cm. Cost: still dry (theta ~0.11 est.), vapor conductivity changes; needs re-check that the on/off difference is visible.
- B (smaller steps): `SELECTOR.IN:32` `0.1 0.01 0.5 1.2 0.5 1 20 4` -> `0.001 0.00001 0.05 1.2 0.5 1 20 4` (dt, dtMin, dtMax). Tests the step-size hypothesis alone.
- C (weaker thermal forcing): top/bottom heat BC `SELECTOR.IN:45` `1 45 1 5` -> `1 25 1 15` plus PROFILE.DAT temperature column linear 25->15 (this one change needs 2 files because the profile must match the BC). Cuts the vapor flux roughly 4x.
Order of preference for the final deck: A if it converges; B alone is expected to fail (my prediction, to be tested).
