# 31.3.3 -- Meteo.in reader

## Goal
Hand-written, dependency-free reader for `Meteo.in` (Gate A scope: `iCrop=0`, `lMetDaily=f`). `meteo::config::MeteoConfig` from `MeteoIn` (`INPUT.FOR:934-1066`); `meteo::series::MeteoRecord` Vec from the `SetMeteo` reads (`TIME.FOR:484-497`). Contract section 7 rejections raised as typed `MeteoError` before any state change. Other modes rejected with a trigger.

## Notes
- Existing `meteo/mod.rs` already defines `MeteoError`, `RadiationParams`, mode enums with `TryFrom<i32>`. Variants already present: `InvalidTemperatureRange`, `RelativeHumidityOutOfRange`, `NegativeWindSpeed`, `NegativeRadiation`, `UnsupportedRadiationMode`, `CropHeightExceedsMeasurementHeight`, `SurfaceEnergyBalanceUnsupported`. Mismatches with the spec: `InvalidMeteoDeck` is `{ reason: &'static str }` (no `path`), and `GrowthTableOverflow` does not exist. `InvalidMeteoDeck` is not used elsewhere in the crate.
- Mapping to Fortran quirks: `iRadiation=2` skips latitude/coeff block (Altitude=0); that mode is rejected under Gate A scope but the grammar is kept in mind. `iSunSh=3` with `iRadiation=1` reads an extra Ac/Bc line (rejected under scope).
- Fortran `read(33,*)` header skips consume whole lines; data lines are list-directed, so extra trailing tokens are ignored, and a `/` ends input. I will treat `/` as unsupported -> InvalidMeteoDeck.
- Scratch under `.development/31.3.3/` if needed. No edits to radiation.rs, water_solver.rs, criteria.json, src_reference.
