## Notes
Files edited: `adapter/reactions.rs`, `adapter/transport_properties.rs`, this todo, and scratch only. `fields.rs` already has `present`, `decode_unit_value`, `map_available` and `UnitValue: Deserialize`, so nothing is missing.

Old shapes and coercions (all wrapped as `{units, value | availability+reason}`, with the units string checked first):
- `coordinates` (units `cm`): object `{native, canonical, nodes}`, all required. native/canonical are nonempty strings (`as_string`). nodes is an unsigned integer (`as_u64`, so a float or negative is rejected), and 0 is rejected. Unknown key rejected. No optional fields.
  - DTO: `native: String, canonical: String, nodes: usize`. `TryFrom` rechecks nonempty and nodes>0.
- `moisture_dependency` (units "source selector and WDep table"): `{selector, table}`.
  - selector: required `u8` (`as_u8`, float/out-of-range rejected), then >2 rejected.
  - table: optional and absent means `[]`. An explicit `null` is rejected (`number_vec` needs an array). Elements are finite f64; an integer is accepted. selector==1 with an empty table is rejected.
  - DTO: `selector: u8, #[serde(default)] table: Vec<f64>`. A plain `Vec` with `default` already rejects `null`, so `present` is not needed. `TryFrom` keeps the two checks and maps `DefaultReal::from_input`.
- `ordered_species`: array of `{name, position, chain_rate_per_hour, initial_concentration_C_ref, linear_equilibrium_kd_cm3_per_g}`, all required.
  - name is a nonempty string, position is `usize`, the rest are finite f64. Unknown key rejected.
  - DTO uses `#[serde(rename = "initial_concentration_C_ref")]` for the mixed-case key. `TryFrom` rechecks name nonempty.
  - Per-entry old errors are `ordered_species.<key>`; new errors name the group (`field ordered_species`) or the missing key.
- `material_species_chpar` and `chpar_records(value, name)`: array of `{species, material, slots}`, all required. species/material are `usize`. slots are finite f64 and must have length exactly 20. Unknown key rejected.
  - `chpar_records` stays `(&Value, &str) -> Result<Vec<MaterialSpeciesParameters>, String>`, because `transport.rs` passes `source_chpar` as a raw `Value` with the name `endpoint_primitives.source_chpar`.
  - Implementation: `serde_json::from_value::<Vec<ChparEntryDto>>(value.clone())`, mapping errors to `format!("field {name}: {e}")` with the same `unknown nested key` rewrite as `decode_unit_value`. Then check the slot length and convert.
  - `maybe_chpar` stays `unit_value(..., |x| chpar_records(x, name))`: it must NOT use `decode_unit_value::<Dto>`, because the Value-based `chpar_records` is the single shared path.

ADR-0004 differences:
- Explicit `null`: no DTO here has an `Option` field. `table` is a defaulted `Vec`, which serde rejects for null. The wrapper's `value: null` goes through `present` in `Wire`. Tests cover null for table and for a required key.
- Integer vs float: all integer fields are `usize`/`u8`, which serde_json rejects for `3.0` and `-1` just as `as_u64` does. Tests with `nodes: 3.0`, `selector: 1.0`, `species: 1.0`.
- Missing `units`: handled by `Wire`/`field_value`, and the old `expect_units` is kept. Tests cover missing units and wrong units.
- Extra hazard I will test: serde derive structs also accept a JSON array as a tuple (`visit_seq`), which the old `as_object` rejected. Tests pass `[...]` as the value or as an entry for each DTO.
  - If any is accepted after the change, I decode through `serde_json::Value` with an explicit `is_object` guard (or a `#[serde(try_from = "Value")]`-style guard) in my own files only.
- Unknown nested key: `deny_unknown_fields`. The `decode_unit_value` rewrite keeps the text `unknown nested key X`. `chpar_records` repeats that rewrite locally.
- Non-finite numbers: JSON cannot carry them, and the `finite_tree` pre-pass runs before the mappers. I keep an `is_finite` check in `TryFrom` anyway for parity with `as_f64`.
- Absent-key defaults: only `table` (default empty). No other defaults exist in these groups.
