## Notes
Reproduction: the harness `requested_study` only accepts roots under `.development/{13.2.2,13.3.1,13.4.1,13.6.1}` and file name `observations.json`; I used `<worktree>/.development/13.2.2/{dc,rz}/observations.json` (untracked/ignored). Both outputs are byte-identical to the 22.3.3 observations (dc: node0 1.25->0, interior frozen; rz: node0 1->0).
Root causes (public path `solute.rs` vs deck runner, which loads `ChPar` per the deck: `deck_reader.rs:705-724`, `bc kTopCh/kBotCh`):
1. `solute.rs:1026,1047`: `face_dispersion.first()` (an effective D, cm2/h) is written into `ch_par[1]`, a longitudinal dispersivity. Kernel `transport.rs:90`: `D = dispersivity*|v|/theta + Dw*tau + ...`, `Dw` read from `ch_par[jjj+4]` (`driver.rs:956`), never set by the public path (`ch_par_row.fill(0.0)` at :1045). With q=0 the dispersion is exactly 0 -> interior frozen. With q!=0 D is also misread (D multiplied by |v|/theta).
2. `solute.rs:969-977,1003-1007`: `TotalFlux` with `|v|<=1e-30` selects `k=+1` (Dirichlet), and `c_bot = flux` (a flux written as a concentration; 0 for the zero-flux inlet). Node 0 is pinned to 0 (`boundary.rs:392`). Deck code `-1` with no inflow yields the natural row (`boundary.rs:398`).
3. `solute.rs:1103`: first-order `decay_rate` written to `ch_par[offset+13]` = 1-based `jjj+14` = `gam_l1` (chain production term, `driver.rs:967`), not `gam_l`/`gam_s` (`jjj+11`/`jjj+12`, `driver.rs:962-964`). Not exercised by the 22.3.3 hand runs (rates were 0), but the public path would apply no decay to species 0; found while checking the "reaction_zero rate and sink mapping" suspect. `reaction_zero` in CASES_V2 has rate 0 for all species (no zero-order field exists in `SoluteSpecies`), so its failure is cause 2 only.
Checked and not causes: `kd`/`nu`/`beta` slots (`offset+6/7/8` = 1-based `jjj+7/8/9`) match the deck layout; omega slot `offset+19` matches `driver.rs:978`; `dt_min` and `water_flow` differences vs the deck runner are noted by 22.3.3 and are not defects for prescribed water.
Open/discovered (not fixed): kernel velocity per node is set from `face_fluxes[i]` (`solute.rs:~1190`, lower face of each node) and `th_o/th_n` per node; fine for uniform q, not for strongly nonuniform flux. `face_dispersion` is per face but the kernel takes one D per material; plan: use the mean of `face_dispersion` over the faces adjacent to nodes of that material (exact for the uniform case; documented limit).
Files: edit `crates/hydrus-core/src/solute.rs` (~:969-1110, plus in-file tests only if a pinned test requires it); create `crates/hydrus-core/tests/solute_fortran_public_path.rs`, `planning/tasks/22.3.5.todo.md`; scratch `.development/22.3.5/`. Orchestrator re-pins `POLICY_HASHES` for `solute.rs`.
