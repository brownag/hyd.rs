# Task 3.1.1 micro-plan — Bootstrap the hydraulic-core contract

1. Create the minimal Cargo workspace and `hydrus-core` package in the permitted files, with no runtime, filesystem, solver, mesh, I/O, or host dependencies.
2. Define the public crate surface in `crates/hydrus-core/src/lib.rs`, including the hydraulic module, validated parameter/result/derivative types, and the typed error boundary.
3. Implement `error.rs` with distinct error variants for non-finite/invalid parameters, invalid evaluation domain, invalid table configuration, and unsupported selectors; expose stable diagnostics without fallback behavior.
4. Implement `hydraulics/types.rs` with constructible-only-through-validation van Genuchten parameters and finite evaluation/derivative result types, using explicit invariants and no formula implementation.
5. Implement `hydraulics/mod.rs` with centralized selector handling, the `HydraulicModel` contract, `HydraulicTables` placeholder contract, and typed rejection for nonzero/unsupported selectors; keep the API filesystem-free.
6. Add `crates/hydrus-core/tests/api_contract.rs` covering public construction, validation failures for non-finite/invalid parameters and domains/table configuration, and typed failures for nonzero and unsupported selectors without model-0 fallback.
7. Run the required targeted contract test: `cargo test -p hydrus-core --test api_contract`.
8. Run the required quality checks: `cargo fmt --check` and `cargo clippy -p hydrus-core --all-targets -- -D warnings`; inspect the diff to confirm only the task’s listed files are touched and no source-reference/Fortran/solver/mesh/I/O/host files appear.
9. After all checks pass, append the concise task report under `## 3.1.1` in `planning/STATE_3.md`, limited to 15 lines and recording the exact commands/results and scope boundary.
