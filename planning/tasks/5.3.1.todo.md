# Task 5.3.1 micro-plan — Implement transactional Picard water stepping

## Goal

Add a filesystem-free, `f64` single-domain Picard water-step contract that uses the Phase 2 interior stencil, generic endpoint rows, and the in-place Thomas kernel; it will preallocate fixed-size state/workspace, commit only accepted trials, retry rejected trials with a reduced timestep, and report finite convergence/pivot/balance diagnostics without adding physical boundary or forcing policy.

## Notes

- `WATFLOW.FOR:48-168` supplies the Picard/iteration/retry shape; the Rust contract deliberately uses strict typed pivot/non-convergence failures instead of source tiny-pivot substitution or continuation. Source `dt / 3` retry is the proposed deterministic reduction, bounded by `dt_min`.
- `WATFLOW.FOR:173-353` provides the Phase 2 `Reset` algebra and boundary-aware solve context; Phase 3 consumes caller-prepared generic `BoundaryCondition` rows and must not implement `Shift`, atmospheric/ponding/seepage switching, fixed-head/flux/free-drainage policy, or root forcing.
- `WATFLOW.FOR:1079-1125` and `STATE_AND_CALLS.md#rollback` require accepted-only promotion. Phase 3 snapshots only its single-domain water state, workspace-tracked trial/accounting data, and does not imply rollback coverage for later heat, solute, vapor, hysteresis, or dual-porosity state.
- The balance is a Phase 3 numerical diagnostic based on supplied storage/flux/sink terms, not a physical-boundary or fixture-parity claim. Define and test the zero-denominator normalization explicitly during implementation.
- Fixed-size allocation proof is scoped to the solver path after construction/setup; it excludes setup/resizing and error construction, follows `VALIDATION_STRATEGY.md#allocation-and-performance`, and makes no performance or Fortran-parity claim.
- Preserve the `f64` contract and existing Phase 1/2 behavior. Do not add dependencies, transport/general-band solving, I/O, CLI/host behavior, event alignment, or optional physics.
