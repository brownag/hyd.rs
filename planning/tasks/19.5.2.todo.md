## Notes
Files edited: adapter/{biology,nonequilibrium,source_coupling}.rs, this todo. Wrappers `validate_dual_domain_dimensions`, `validate_source_coupling_guards`, and the `dual_domain::validate` / `validate_uptake` / `validate_exclusion` calls are untouched.

Old shapes and coercions (all: units checked first, value must be object, unknown key rejected, number = finite f64 accepting ints, ints = JSON u64/i64 only so floats like 1.0 rejected, u8 range-checked, explicit null always rejected unless noted):
- biology_mode {iBact:u8 default 0, lFiltr:bool default false}. Null for either key is rejected (get -> Some(null) -> as_* fails). DTO: `#[serde(default)]` on non-Option u8/bool (not Option), so null is rejected.
- biology_parameters {blocking_iPsi:u8?, grain_diameter, particle_diameter, attachment_capacity_1, attachment_rate_1: f64?}: all optional AND null == absent (explicit `None | Some(Null)`). DTO: `Option<..>` with plain `#[serde(default)]` (NOT `present`) so null -> None; `#[serde(rename="blocking_iPsi")]`.
- dual_domain {dynamic_exchange_claimed:bool default false, iDualPor:u8 required, water_model:u8 required}. DTO: bool `#[serde(default)]`; required u8s plain; rename iDualPor.
- dual_porosity_material: record must be object; required f64: mobile_residual_water, mobile_saturated_water, immobile_residual_water, immobile_saturated_water, immobile_alpha; optional f64 (null rejected): mobile_tortuosity, immobile_n, immobile_saturated_conductivity -> `#[serde(default, deserialize_with="present")] Option<f64>`.
- dual_porosity_exchange_state: required Vec<f64> coordinates, old_water, new_pressure_head, old_immobile_water; material_ids Vec<usize>; materials Vec<DualPorMaterialDto>; f64 critical_atmospheric_head, dt; i32 hydraulic_model; u8 dual_porosity. All required, none nullable.
- control_switches {lWat, SinkF}: both required bool (renames), unknown keys rejected.
- root_uptake_state: required usize species, species_count; f64 time (DoubleReal(f64), not DefaultReal -> keep the `DoubleReal(d.time)` conversion); Vec<f64> coordinates, root_distribution, root_water_sink, species_concentration; f64 omega_water, species_root_max_concentration, solute_stress_index, potential_uptake, michaelis_constant, minimum_concentration; bool `lActRSU` (rename -> active_uptake). All required.
- size_exclusion_state: usize nodes; f64 mobile_residual_water, mobile_saturated_water, mobile_n, mobile_tortuosity, colloid_exclusion_water_content, first_node_new_water, first_node_new_velocity. All required.
- Explicit/unavailable forms handled by the shared `UnitValue<T>` Deserialize via `decode_unit_value` (unchanged helper); `map_available` converts only Available.

ADR-0004 differences and handling:
- null vs absent: `present` for nullable-reject optionals; plain `default` where old code treated null as absent (biology_parameters only).
- Defaults: non-Option `#[serde(default)]` so null is still rejected (biology_mode, dynamic_exchange_claimed).
- Int vs float: serde u8/usize/i32 reject floats like 1.0 same as `as_u64/as_i64`; negative rejected for unsigned. f64 fields accept ints like `as_f64`. Nonfinite cannot occur from JSON text in either path (will confirm via a 1e999 test).
- Error text changes (nested keys now named by serde); tests assert field/key names with `a|b` alternatives.
- Message-only difference: old code reported a missing key as "X missing/requires"; serde says "missing field `x`". Still a rejection of the same request.
- Item-level vec checks: old `number_vec` error named the array; serde names the index. Rejection set identical.
- Duplicate keys already rejected upstream by `reject_duplicate_keys`.

Planned tests per file (assert field/key name, not text): null for a required field, null for a nullable-optional (except biology_parameters where null is ACCEPTED, tested as acceptance), wrong type (string for number/bool), float for integer (iDualPor 1.0, species 1.0, nodes 2.0), missing units, unknown nested key (top-level and inside a `materials` record), missing required key, negative for unsigned, out-of-range u8 (256), plus one accept test for defaults and `Explicit` unavailable form.
Array-as-struct guard (orchestrator note): serde structs accept arrays positionally; old `as_object` did not. Each mapper first peeks `fields.get(name).and_then(|w| w.get("value"))` and, if present, calls `require_object(v, name)` before `decode_unit_value` (covers the wrapper `value`; null/scalars also fail there, still a rejection). Levels: biology_mode, biology_parameters, dual_domain, control_switches, root_uptake_state, size_exclusion_state, dual_porosity_exchange_state = wrapper value only; dual_porosity_exchange_state additionally checks each element of `materials` (if it is an array) with `require_object(el, "dual_porosity_exchange_state.materials")` before decoding; `dual_porosity_material(&Value)` calls it on its record before `from_value`. No other nested struct levels exist (other nested values are Vec<f64>/Vec<usize> arrays, which are meant to be arrays). Extra tests per file: array-as-struct at the wrapper value (e.g. `[1,2]`, `[0,6]`), and for nonequilibrium an array as a materials element and as a direct `dual_porosity_material` record.
