Proposed `pub(crate)` interface (in `atmospheric.rs`; `impl` on a small Copy struct, mirroring `LowerBoundaryMode::prepare_step`):
```rust
#[derive(Clone, Copy)]
pub(crate) struct AtmosphericAssembly { pub rates: AtmosphericRates, pub upper_mode: UpperBoundaryMode, pub ponded_depth: f64 } // moved as is
pub(crate) struct AtmosphericUpperPlan { pub condition: BoundaryCondition, pub row: BoundaryRow, pub mode: UpperBoundaryMode }
pub(crate) struct AtmosphericTransitionDecision { pub soil_flux: f64, pub ponded_depth: f64, pub atmospheric_exchange: f64, pub stable: bool }
impl AtmosphericAssembly {
    // assemble path: top flux, hCritA, mode, row, condition
    pub(crate) fn prepare_step(self, workspace: &WaterWorkspace, state: &WaterState,
        input: WaterStepInput<'_>, timestep: f64) -> Result<AtmosphericUpperPlan, WaterStepError>;
}
// solve_trial path, after head update
pub(crate) fn decide_transition(rates: AtmosphericRates, upper_mode: UpperBoundaryMode,
    workspace: &mut WaterWorkspace, state: &WaterState, input: WaterStepInput<'_>,
    timestep: f64) -> Result<AtmosphericTransitionDecision, WaterStepError>;
fn critical_head(c: BoundaryCondition) -> Result<f64, WaterStepError>;          // private, the single hCritA match
pub(crate) fn top_row_for_trial(...) -> Result<BoundaryRow, _>;                 // was atmospheric_top_row
fn mode_for(...) / top_flux_from_workspace(...) / top_flux_for_heads(...)       // were atmospheric_mode / _top_flux / _top_flux_for_heads
```
Names are refinable; final names must not start with `atmospheric_` as a `fn` in `water_solver.rs`. `BoundaryRow`, `validate_finite` and `transform_boundary_row` stay in `water_solver.rs` (or their current module) and are imported via `crate::` if `pub(crate)`; if they are private, I will make them `pub(crate)` in `water_solver.rs` (allowed, my file). Question 1 covers where they live.

Statement order preserved:
- `prepare_step` (from `assemble`): `head`/`demand` locals, then `top_flux` (reads workspace), then `critical_head?` (error), then `mode`, then `top_row?`, then condition (Dirichlet{critical_head} if PondedHead else Neumann{flux: demand}). Error precedence unchanged.
- `decide_transition` (from `solve_trial`): `demand = net_flux`; `soil_flux` = `top_flux_for_heads?` if `upper_mode == PondedHead` else demand; `ponded_depth = (state.ponded + (demand - soil_flux) * timestep).max(0.0)`; `atmospheric_exchange = soil_flux + (ponded - state.ponded) / timestep`; `critical_head?`; `mode_for`; stable = (next == upper_mode); if unstable: `top_flux_for_heads?`, candidate storage, write `workspace.atmospheric_transitions[count]` then `count += 1`. `solve_trial` keeps assigning `soil_flux`, `ponded_depth`, `atmospheric_exchange` and `active_set_stable` in the same position, and still resets `atmospheric_transition_count = 0` before the loop (stays in `solve_trial`).

WaterWorkspace fields (all existing `pub(crate)`, `water_state.rs` unchanged):
- reads: `trial_heads`, `evaluated_conductivity`, `evaluated_theta`, `evaluated_capacity`, `trial_sink`, `node_count()`; `state.water_contents`, `state.atmospheric.ponded_depth`; `input.mesh` (coordinates, material_indices, inclination_cosine), `input.materials`, `input.upper_condition`.
- writes: `atmospheric_transitions[..]` and `atmospheric_transition_count` (in `decide_transition` only). `assemble` still writes the other fields itself.

Top-flux merge: NOT merging. The two differ in data source: `atmospheric_top_flux` reads workspace `evaluated_conductivity`/`evaluated_theta` (infallible, no finite check); `_for_heads` re-evaluates materials at `trial_heads` (fallible, with finite checks, different value after the Newton update). A merged function would need a branch or closure for the inputs; it could keep operand order but the saving is a few lines and the risk to D8 is real. Move both verbatim, with a shared nothing. (Spec: "Otherwise move both".)

Unit tests (in `atmospheric.rs`, no full step; build a small `WaterWorkspace` + mesh + materials from the helpers the existing tests use; if no helper is visible to lib tests I will build a 2-node mesh inline):
1. `mode_switches_to_head_when_top_head_exceeds_critical_for_infiltration` and the evaporation mirror, plus return to `AtmosphericFlux` when not ponded and supply satisfies demand (pure `mode_for` truth table).
2. `ponding_onset_and_drain`: `decide_transition` from `AtmosphericFlux` with top head > critical gives `stable == false` and records one transition (count 1, correct `from_mode`/`to_mode`); from `PondedHead` with positive candidate depth stays ponded and `ponded_depth` grows/drains by `(demand - soil_flux) * dt`, clamped at 0.
3. `critical_head_requires_dirichlet`: non-Dirichlet upper condition returns `UnsupportedAtmosphericInput`; Dirichlet returns `value`; `prepare_step` returns a Dirichlet condition in `PondedHead` and Neumann{flux: demand} in `AtmosphericFlux`.
