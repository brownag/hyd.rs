# 14.2.1 — Add field-aware printed-parity comparison

## Goal
Create a read-only comparator that authenticates retained inputs and compares semantically equivalent Fortran printed fields to Rust binary64 observations using the Fortran field’s actual print interval.

## TODO items
- [ ] Reuse `solute_printed_parity_inventory.py` validation/inventory patterns, `solute_verification_metrics.py` raw readers and `rounding_half_width`, `run_solute_verification_reference.py:FIELD_FORMATS`, and bridge interval parsing as scoped by the task spec.
- [ ] Define explicit field mappings from Fortran raw records to Rust observations, including coordinate/time/species keys and validated orientation/sign conventions; leave unsupported or semantically incompatible fields unavailable, especially Fortran nonequilibrium `Sorb` versus Rust equilibrium storage.
- [ ] Authenticate Fortran manifests/artifact hashes and Rust observation artifacts/configuration/schedule before parsing; fail closed on any mismatch and never write to retained artifact paths.
- [ ] Parse the selected raw Fortran fields while retaining each original numeric token and its per-field format; parse corresponding Rust values as binary64 and preserve signed `Rust - Fortran` differences.
- [ ] Derive each printed interval using `metrics.rounding_half_width` and the actual field format/exponent, with robust edge comparisons that do not widen intervals through a global tolerance.
- [ ] Emit per-comparison `pass`, `fail`, or `unavailable` records with raw values, interval, format, coordinates/time/species, and reason; add a separate `low_information` diagnostic when half-width is at least `abs(Rust)` or Rust is zero.

## Discovered
- Selected raw format families expected from the format tables include `e12.4` concentration/profile values, `e13.5` solute flux values, and fixed coordinate formats such as `f10.4`. The implementation must map actual fields through the named readers rather than infer semantics from names alone.
