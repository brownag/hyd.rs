## Discovered (defects in the pre-task implementation, each with source evidence)

1. **Rows must be composed across levels.** `F(1)` is written at `792` (Level 1) and then read
   and extended at `814`; `F(N)` at `881/882/891` and then at `914/915`. The current
   `endpoint_row(state, level, …)` returns two independent rows, so neither call yields the value
   `BanSol` consumes, and summing them double-counts the absolute cases (`806`, `908`, `818`, `826`).
2. **The prescribed-code flux used the boundary row instead of the natural coefficients.**
   `221` uses `D1,E1,F1` and `204` uses `BN,DN,FN`; `F1`/`FN` are the Level-1 values plus `F2`/`FE`
   (`800`, `902`). The current `endpoint_flux` calls `endpoint_row(New, …, 1)`, i.e. for `kBotCh=1`
   it forms `1·C1 + 0·C2 − cBot` (the boundary equation), and for the top it feeds the
   atmospheric-perturbed row into the residual.
3. **`dSurfT` is shared.** `81` computes `dSurfT = dSurf*exp(TDep(jjj+9)*TT(TempO))` and `891`,
   `924`, `211-212` all use it; `MatSet`'s `dSurf` formal *is* `dSurfT` (`127`). Current
   `atmospheric_terms` uses raw `dSurf`, and `atmospheric_flux_terms` recomputes the factor from
   `TempN`.
4. **`ChPar`/`TDep` indexing was wrong.** `889-890`/`922-923` read `ChPar((jS−1)·16+6, M)` and
   `ChPar((jS−1)·16+10, M)` — material is the *outer* array dimension — while the current code
   indexes a flat vector as `species_base + material*20 + 5`. `TDep` is 1-D with a 16 stride per
   species; the adapter's `(max_material−1)*20` stride check is wrong for it.
5. **Absolute assignments were treated as natural rows.** `806` `F(1)=cBot` and `908` `F(N)=cTop`
   (plus `B(N)=0`, `D(N)=1`) overwrite everything accumulated earlier; the current code returns
   the natural diagonal/rhs for code 1 (and its test asserts that).
6. **`kTopCh == −2` was excluded from the Level-2 prescribed term.** `915` runs for every
   `kTopCh ≤ 0` including `−2`; the current code guards `code != -2`.
7. **Level-2 atmospheric RHS does not exist.** `924` only adds to `D(N)`; `cAtm` enters `F(N)`
   once, at Level 1 with a **plus** sign (`891`). The current code subtracts `cAtm` at Level 2 and
   omits it at Level 1.
8. **Level-1 prescribed terms were applied for codes > 0.** `880` guards the whole Level-1 upper
   block with `kTopCh.le.0`; the current code applies the `vO(N)<0` term and the atmospheric term
   regardless of the code, and `boundary.rs:233-237` invents
   `F(1) = old_accepted_concentration(1)` at Level 1 for code 1 (no such statement in the source).
9. **Two different velocity states are mixed.** Inside `MatSet` (`792`, `797-798`, `814`, `870-877`,
   `882`, `895-900`, `915`) `vO`/`vN` are the pre-`vCorr` arrays; `65-72` and `197-221` use the
   restored entry values (`129-132`). Current row code uses `old_velocity` in `F1`/`FN` but
   `old_matrix_velocity` for `792`, and the flux uses `new_velocity` for both phases.
10. **Flux phases were not summed and used the wrong weights/concentrations.** Phase A needs
    `alf` + `old_concentration` + entry `vO` (`65-69`), phase B `epsi` + post-solve `Conc` + entry
    `vN` (`215-219`); `218-219` accumulate while `221` assigns. The current per-level
    `endpoint_flux` uses `epsi`/`new_velocity`/`accepted` in both phases, so a bottom free-drainage
    step returns `epsi·C_new·vN` twice instead of `alf·C_old·vO + epsi·C_new·vN`.
11. **Precision grouping.** `762` makes `B,D,E,F` double; `792` computes its whole RHS in REAL and
    stores it to `F(1)`, while `814`/`914`/`924` accumulate into the double in double arithmetic
    after computing their REAL products. Bit-level parity work needs that split; the current code
    widens ad hoc.
12. **Unused required inputs.** `old_accepted_flow`, `new_accepted_flow`,
    `old_accepted_concentration`, `henry_coefficient`, `gas_diffusion` are not arguments of
    `MatSet` or of the flux block; they are currently mandatory request fields that the kernel
    silently ignores (two of them also feed the invented behavior in item 8).
13. **Not kernel behavior.** `60-63` zeroes `cBot(jS)`/`cTop(jS)` when
    `t−tPulse > dtMin .and. .not.AtmBC`, and `772` writes a `ThImob > Theta` warning: both are
    caller/step-level effects to be owned by the step driver, noted so the values passed as
    primitives are understood to be post-zeroing.
14. **Not `MatSet` code.** The `Thj/Disj` text at `746-748` continues `call PeCour(...)` in `Coeff`
    (`746`), not an endpoint statement; only `755-939` is `MatSet`.
15. The task file's verification line says 7 boundary tests; HEAD has 9 (two were added by the
    18.7.4/amendment round). No adapter test parses `endpoint_primitives` at all today, and no
    fixture JSON contains that key, so the request shape is still internal to these three files.
16. **Found while implementing:** the adapter validated `material_immobile_water` against the node
    count. `ChPar(4, M)` (`771`) is indexed by material, so a three-node/two-material bundle was
    rejected; it is now checked against `mobile_immobile` (the material count) like the kernel,
    and pinned by a test.
