# Task 4.2.1 micro-plan — Add mesh geometry, layer metrics, and face averaging

## Goal

Add pure, filesystem-free geometry helpers over `Mesh1D` for node distances, boundary half-cells, layer metrics, inclination/gravity access, and explicit arithmetic or geometric face-conductivity averaging.

## Steps

1. Re-read the accepted 4.1.1 report and confirm the permitted boundary: only `crates/hydrus-core/src/hydraulics/mod.rs`, new `geometry.rs`, new `mesh_geometry.rs`, and this TODO may change; preserve signed coordinates and zero-based mesh data.
2. Inspect the existing `Mesh1D` accessors and `HydraulicError` conventions, then define a small public geometry API whose names make node, boundary-half-cell, layer, inclination/gravity, and face concepts explicit.
3. Implement finite adjacent-distance helpers over strictly increasing coordinates, including exact source-style boundary half-cell widths and interior left/right distances; retain coordinate orientation in returned signed or documented positive widths as appropriate.
4. Implement layer grouping/span/metric helpers using the optional zero-based layer indices and declared layer count, with typed rejection for absent layers, invalid layer references, empty groups, or non-finite derived values rather than silent defaults.
5. Expose the validated inclination cosine and the gravity metric through explicit helpers, documenting the source convention `Grav = CosAlf` and keeping any sign/orientation behavior visible in API names/docs.
6. Implement explicit arithmetic and geometric face-conductivity averaging functions over finite conductivity pairs; reject non-finite inputs and invalid geometric means (including negative values) with typed errors, without silently selecting arithmetic averaging.
7. Register the geometry module and its intended public exports in `crates/hydrus-core/src/hydraulics/mod.rs` only; add no stencil, coefficient, boundary-condition, solver, filesystem, or third-party dependency behavior.
8. Add `crates/hydrus-core/tests/mesh_geometry.rs` covering boundary and interior distances, exact half-cell results, signed/nonuniform coordinates, layer grouping and spans, inclination/gravity access, arithmetic versus geometric means, finite-value rejection, negative geometric inputs, and optional-layer/domain failures.
9. Run the targeted acceptance checks: `cargo test -p hydrus-core --test mesh_geometry`, `cargo fmt --check`, and `cargo clippy -p hydrus-core --all-targets -- -D warnings`; inspect `git diff --check` and verify the diff stays within the declared files.
10. Report the implemented API, source-algebra/terminology boundaries, exact verification results, and any unresolved layer-metric interpretation to the orchestrator; do not update `STATE_4.md` or claim Fortran parity, fixture agreement, solver behavior, or performance evidence.
