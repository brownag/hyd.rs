# Task 5.2.1 micro-plan — Implement the water tridiagonal kernel

## Goal

Add a filesystem-free, allocation-free-in-use, in-place Thomas-style tridiagonal water kernel over caller-owned `f64` lower/diagonal/upper/RHS buffers. It will leave the solved values in RHS, report the minimum pivot diagnostic, and return typed invalid-input or singular/near-zero-pivot errors without encoding water boundary policy or transport behavior.

## Steps

1. [x] Reconfirmed the completed 5.1.1 endpoint-row contract, the Phase 2 interior-row convention, the scoped file boundary, and the existing `HydraulicError` conventions; preserved unrelated dirty worktree changes.
2. [x] Defined the smallest public `linear.rs` contract: an in-place solver function taking mutable caller-owned coefficient/RHS slices and an explicit positive finite minimum-pivot threshold, plus public typed kernel error and pivot-diagnostic types local to the linear module.
3. [x] Documented the zero-based equation convention (`lower[i] * x[i - 1] + diagonal[i] * x[i] + upper[i] * x[i + 1] = rhs[i]`), required inactive endpoint off-diagonals, the fact that RHS is overwritten with the solution, and that callers assemble boundary rows before invoking the kernel.
4. [x] Validated before elimination that the system has a supported nonzero dimension, all four buffers have identical lengths, the inactive endpoint entries are zero, the threshold is finite and positive, and every input coefficient/RHS is finite; typed preflight failures leave mutable buffers unchanged.
5. [x] Implemented forward Thomas elimination in place by modifying diagonal and RHS only, checking each divisor before use against the threshold and tracking the least absolute accepted pivot; it does not allocate, resize, clamp, or silently substitute a pivot.
6. [x] Implemented backward substitution into RHS, applying the same finite/pivot checks to the terminal and remaining diagonal pivots; it returns the minimum-pivot diagnostic only after a complete solve.
7. [x] Kept `Gauss` boundary transformations, `rMin` compatibility clamping, `sngl` conversion, general/banded or transport solving, mesh/hydraulic evaluation, Picard/retry state, and all physical boundary/forcing policy out of this module.
8. [x] Registered the private module and exported only the intended kernel API, diagnostic, and typed error from `hydraulics/mod.rs`; did not alter `error.rs`, `lib.rs`, or other production files.
9. [x] Added `tests/tridiagonal.rs` with hand-solved systems and a larger system, asserting RHS solution values and the minimum-pivot diagnostic against independently calculated expectations.
10. [x] Added typed failure tests for zero/near-zero forward and terminal pivots, non-finite threshold/buffer entries, mismatched or empty buffers, invalid endpoint off-diagonals, and verified failed preflight leaves the input buffers unchanged.
11. [x] Added a buffer-reuse test that restores caller-owned coefficient/RHS values between solves and confirms the same mutable buffers can be solved repeatedly with no solver-owned allocation or retained state.
12. [x] Ran only `cargo test -p hydrus-core --test tridiagonal` (5 passed after one floating-point assertion correction), `cargo fmt --check`, `cargo clippy -p hydrus-core --all-targets -- -D warnings`, and `git diff --check`; report exact results, the absence of Fortran-parity claims, and the Phase 3.1 integration handoff without updating `STATE_5.md`.

## Notes

- `WATFLOW.FOR:308-353` is boundary-aware water elimination with small-pivot substitution. The kernel instead receives already-prepared generic rows from 5.1.1 and produces strict typed singular/near-zero diagnostics; a compatibility clamp is deferred to a later explicit policy.
- `SOLUTE.FOR:945-957` confirms the forward/back tridiagonal algebra but is transport behavior and must not become a shared transport solver or expand this task.
- The source and master evidence require `f64` numerical paths. The kernel mutates only caller-owned fixed-size buffers and owns no workspace, so it fits the later preallocated `SimulationWorkspace` boundary.
- Tests are Rust contract/source-algebra evidence only, not a Fortran parity, precision-calibration, allocation-benchmark, or physical-water acceptance result.
