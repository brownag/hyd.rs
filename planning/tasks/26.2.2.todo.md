### Risks

- Build time: not recorded in any STATE file. Use a background run with a log and a long timeout.
- Executable hash: the rebuild may not reproduce `824179ab…`. It may differ because of GNU Fortran version, host, or build paths. Record it; do not claim equality.
- NaN or instability: 25.2.2 had two NaN attempts (STATE_25 `:179`). Water dt-cut logic (`:224-230`) can stall or diverge. A failing case leaves its `<task-base>/<id>/` root and no fixture; the producer is not idempotent per run root, so a retry needs a new `--task-base` (e.g. `.development/26.2.2/runs-2`) and only the failed IDs. Successful fixtures already written stay on disk.
- Partial failure: the loop is sequential, so a failure after N successes leaves N new fixtures. Do not delete them without orchestrator approval.
- `--all` is unusable (see Facts). Using it would abort on the first existing fixture.
- Step 10 cannot rerun the producer for an existing ID (overwrite guard). It uses a direct executable run instead.
