# Task 4.3.1 micro-plan — Port the observed Reset stencil

## Goal

Add a pure, filesystem-free Rust coefficient assembler for the observed `Reset` interior finite-difference rows, preserving source algebra, typed finite/domain failures, and explicit arithmetic versus geometric face averaging.

## Steps

1. Re-read the accepted 4.2.1 report and confirm the permitted change boundary: `crates/hydrus-core/src/hydraulics/mod.rs`, new `stencil.rs`, new `tests/reset_stencil.rs`, and this TODO only.
2. Define the public stencil inputs and documented lower/diagonal/upper/RHS row output over validated `Mesh1D`, including node conductivity/capacity, water-content or storage terms required by the observed formula, timestep, gravity metric, and sink terms.
3. Define an explicit face-averaging selection that defaults to arithmetic and selects geometric averaging only when requested; route all face calculations through the existing geometry helpers without silent fallback.
4. Implement finite/domain validation for mesh size, node arrays, conductivities, capacities, storage/water-content values, timestep, gravity, sink values, and any averaging mode inputs, returning existing typed `HydraulicError` forms or narrowly extending them if required.
5. Implement the source-style interior row assembly for a two-or-more-node mesh: adjacent distances, half-cell width, gravity contribution, capacity/timestep contribution, sink sign, lower/diagonal/upper coefficients, and RHS using the algebra observed in `WATFLOW.FOR:232-256`.
6. Keep boundary rows out of the assembler’s behavior and document that the returned rows represent interior stencil evidence only; do not implement `Shift`, boundary semantics, tridiagonal elimination, convergence, retries, or filesystem access.
7. Register `stencil` and expose only the intended stencil types/functions through `crates/hydrus-core/src/hydraulics/mod.rs`.
8. Add `crates/hydrus-core/tests/reset_stencil.rs` with hand-calculated two-cell/three-cell interior-row cases, checking lower/diagonal/upper/RHS values and source index-to-row mapping.
9. Extend tests for gravity/inclination, storage and timestep contribution, sink sign, arithmetic default versus explicit geometric faces, non-finite inputs, invalid timestep/domain values, mismatched lengths, and insufficient mesh size.
10. Add a test/documentation note stating that the cases validate observed source algebra and are not a Fortran parity result; preserve the finite-difference versus manual finite-element terminology reconciliation as an open validation item.
11. Run `cargo test -p hydrus-core --test reset_stencil`, `cargo fmt --check`, `cargo clippy -p hydrus-core --all-targets -- -D warnings`, and `git diff --check`; inspect that changes stay within the declared files and introduce no solver or filesystem dependency.
12. Report the API, formula coverage, typed-failure behavior, exact verification results, and explicit boundary/solver/parity deferrals to the orchestrator; do not edit `STATE_4.md` or claim numerical parity, fixture agreement, precision compatibility, allocation freedom, or performance.
