## Notes
Files edited: `water_state.rs`, `water_solver.rs`, `solute.rs` (move only), `lib.rs` (only if re-export needs repointing), new `tests/water_solute_coupling.rs`, this todo.

1. Snapshot / solute reading: fields `accepted_time: f64`, `water_contents: &[f64]` (len node_count), `face_fluxes: &[f64]` (len node_count+1: index 0 lower boundary, 1..n-1 interior faces, n upper boundary; node-face values, "positive toward increasing mesh coordinate"). `advance_solute_step` checks both lengths (solute.rs:814-826), checks `accepted_time` against the solute end time within roundoff (:844), reads `face_fluxes[0]`/`[node_count]` for inward-flow-at-outlet checks (:950,:960) and boundary mass (:1030,:1037), and `face_fluxes[face]` as the advecting flux per interior face (:1322, upwinded). Units: water volume per area per time (same as the water balance fluxes). So the buffer is face values, node_count+1, matching the type doc; no conflict.
2. Sign mapping. `balance` terms are "positive = water entering the soil" (`boundary_flux=(lower+upper)*dt`, residual = storage - boundary + sink). Lower entry is toward +x (assumes x increases from lower to upper boundary, as the solute step does via `face_fluxes[0]` as inflow-when-positive at lower and "flux>0 at the upper = outflow"): `face_fluxes[0] = lower_boundary_flux` (the `exchange_flux` returned by `assemble`, carried as `trial.lower_boundary_flux`). Upper entry is toward -x: `face_fluxes[n] = -(soil upper flux)` where soil upper flux is `soil_atmospheric_flux.unwrap_or(input.upper.measured_flux().unwrap_or(0.0))`, the same expression as `soil_boundary_flux` in `balance` (so atmospheric steps use `trial.soil_flux`, not the surface `atmospheric_exchange`; ponding storage is not soil flux). Negation is exact, so endpoints equal the balance's boundary terms bitwise (up to sign). I will pass these values to the fill function from the same locals `balance` receives, not re-derive them. Documented in a comment at the fill site.
3. Interior face flux (new arithmetic, nothing existing changes): `q_f = -K_f * ((h[i+1]-h[i])/dx + gravity)` with `K_f = face_conductivity(K[i],K[i+1],input.face_averaging)` (arithmetic or geometric, the same private `hydraulics/stencil.rs::face_conductivity`, which I would make `pub(crate)`, an edit outside my Must-edit list, see Question 1) and `gravity = input.mesh.inclination_cosine()`. Derived from `ResetRow`: `rhs` has `-(con_a-con_b)*gravity` and off-diagonals `-con/dx`, i.e. dtheta/dt*w = F_b - F_a with F = K(dh/dx + g), so q = -F. Conductivities: `workspace.evaluated_conductivity` is evaluated at the heads entering the last Picard assemble, not at the accepted `trial_heads`; the matrix equations use those same K values, so the accepted solve's own flux is consistent with the solved system (the discrete balance closes with it). Heads: `trial_heads` (accepted). Using the solved system's K and the accepted heads reproduces exactly the row-flux the tridiagonal solve enforced.
4. Filled on acceptance only: inside the `Some(trial)` arm after `balance(..)?` (so a `NonFiniteDiagnostic` error or a retry leaves the buffer as the previous accepted step). Overwritten every accepted step; failed steps leave it stale but the report is not produced. Buffer is allocated at construction, so `allocation_contract` must still pass.
5. Signature: `impl<'a> WaterStepReport<'a> { pub fn accepted_water(&self) -> AcceptedWaterSnapshot<'a> }` (lifetime `'a` is the workspace borrow; the snapshot is `Copy` and can outlive the `&self` borrow). The report has no state reference, so `water_contents` borrows `workspace.trial_water` (equal to `state.water_contents` after acceptance, copied from it); `accepted_time` = report `accepted_time`.
