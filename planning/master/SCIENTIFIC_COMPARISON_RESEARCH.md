# Scientific comparison research: M5 solute

## Purpose and status

This note turns the documented M5 evidence gap into an actionable comparison protocol. **Verified** statements below are grounded in the pinned repository source, local HYDRUS 1D 4.08 manual, and current repository planning/harness records. **Recommendations** describe proposed future work; they are not completed fixtures, accepted tolerances, or a roadmap change.

The current Rust solute tests are deterministic contract/invariant cases, not scientific validation. The Phase 0 Fortran executable has only run the explicitly noncanonical water-only smoke input. No solute input deck, solute oracle output, paired Rust/Fortran comparison, or calibrated tolerance is currently recorded. See [Phase 5 evidence](PHASE_5_SOLUTE_EVIDENCE.md#phase-5-solute-acceptance-evidence), [Phase 0 evidence](PHASE_0_REFERENCE_EVIDENCE.md#smoke-run), and the [smoke input provenance](../../reference/fortran_reference/smoke/README.md).

## What scientific comparison needs

A defensible comparison needs all of the following, kept together as one reviewed fixture record:

1. **A scoped equation/profile:** exact selected physics and source/manual interpretation, including species order, reaction rates, sorption form, transport and boundary modes. Rust currently supports a single water domain, ordered first-order chain, linear or nonlinear equilibrium sorption, one kinetic sorbed pool/species, and selected concentration or inward total-solute-flux endpoint conditions. It does not implement every `SOLUTE.FOR` branch. [M5 scope and equations](PHASE_5_SOLUTE_EVIDENCE.md#delivered-m5-contract); source entry points include [`Solute`](../../src_reference/SOLUTE.FOR#L6), [`Coeff`](../../src_reference/SOLUTE.FOR#L241), [`Disper`](../../src_reference/SOLUTE.FOR#L1025), [`NEquil`](../../src_reference/SOLUTE.FOR#L1078), and [`MassTran`](../../src_reference/SOLUTE.FOR#L1319).
2. **A complete input with provenance:** manual page/table or original case artifact for each parameter; all unspecified values identified, not silently guessed; input hashes and a review record. The local manual documents cases, but does not provide the repository with machine-readable decks or golden output files. [4.08 manual candidate inventory](../HYDRUS_RESEARCH.md#4-validation-research-and-proposed-acceptance-evidence).
3. **A trustworthy reference run:** the pinned source/archive identity, staged compatibility patch, compiler/runtime/flags, executable hash, input hashes, isolated output directory, run logs/status/completion markers, output hashes, and warnings. Existing runner records much of this provenance and rejects incomplete runs; it does not itself interpret or compare scientific values. [Reference harness](../../reference/fortran_reference/README.md#commands), [runner](../../tools/run_fortran_reference.py), [Phase 0 evidence and limits](PHASE_0_REFERENCE_EVIDENCE.md#reference-executable).
4. **Like-for-like Rust inputs and water trajectory:** both solvers must receive the same geometry, units, species/process parameters, initial dissolved/sorbed pools, water content and face-flux history, time interval/event schedule, boundary conditions, and output times. If Fortran water flow is also used, first compare its water trajectory; for isolating M5 transport, feed a recorded common water trajectory to both solute calculations where the interfaces allow it. If that is not possible, characterize water-solver differences before attributing concentration differences to solute code.
5. **Independent observables and an approved tolerance policy:** compare numeric concentration/sorbed profiles and integrated quantities, not just a self-computed balance. Calibrate thresholds per quantity and report residual metrics plus diagnostics. The validation strategy already defines paired absolute/relative tolerance candidates and recommends L-infinity/RMS/mesh-weighted L2, but explicitly states `1e-6` is only a candidate. [Tolerance policy](VALIDATION_STRATEGY.md#tolerance-policy).

### Orchestration 12 fixture audit result

Task 12.1.1 created [`reference/fortran_reference/solute/example3/`](../../reference/fortran_reference/solute/example3/), a **derived executable case motivated by Example 3**, not a recovered deck or manual reproduction. The local workspace contained no original Example 3 input deck or numeric CHAIN arrays. `CASE.json` attributes each manual-transcribed or derived fixture value; `SELECTOR.IN` and `PROFILE.DAT` form the newly authored source input bundle. This bundle has not yet been run through Fortran.

The selected equation profile maps to Rust M5 in principle: with constant `theta` and bulk density, linear equilibrium sorption gives `R = 1 + rho_b*Kd/theta`; the chosen `Kd=0.5375 cm3/g`, `rho_b=0.8 g/cm3`, and `theta=0.43` encode the manual's NH4 retardation factor 2, while zero Kd encodes the NO2/NO3 factors 1. The source `SOLUTE.FOR` transport assembly uses the species retardation in accumulation and forms the sequential source from prior-species first-order liquid and sorbed terms (`GamL1`/`GamS1`); setting both phases to the same rate represents decay/transfer on the selected total species mass. The source dispersion expression is `alpha*abs(v_Darcy)/theta + Dw*TauW`; derived `alpha=0.18 cm`, `Dw=0`, and target `q/theta=1 cm/hour` encode the manual's effective dispersion. These mappings are hypotheses to verify against the actual run's coefficients, realized water trajectory, output and boundary signs before comparing.

The domain length, grid, hydraulic material and boundary pressure heads are derived choices for a finite saturated source run. They differ from the manual's infinite-domain analytical setting. Preserve this distinction in future run reports; compare against an independently calculated analytical solution only after finite-domain, discretization and coordinate effects are characterized. No comparison tolerance or scientific pass is established by defining this case.

## Observable set and extraction

### Compare at matching physical locations and times

- Dissolved concentration `C_i(x,t)` for every chain species at all mesh nodes and agreed observation times. Include the inlet/effluent concentration history (or flux concentration, if the selected boundary formulation exposes it) for pulse/breakthrough cases.
- Sorbed/kinetic pool values where the specific process exists in both models. Do not compare a Rust pool to Fortran's differently defined `Sorb`, `Sorb2`, immobile water, or total sorbed concentration without a documented mapping.
- Integrated species inventories by phase and total per cross-sectional area, using explicitly shared quadrature/control-volume weights. For Rust the documented storage is `sum_j(dx_j * [theta_j*C_ij + rho_b,j*(S_eq,ij + S_kin,ij)])`; Fortran output nomenclature distinguishes `ConcVol` and `ConcVolIm` for its phase/domain definitions. [Rust inventory equation](PHASE_5_SOLUTE_EVIDENCE.md#equations-units-signs-and-water-coupling); manual Table 13.5, printed p. 233 (PDF p. 241).
- Boundary mass fluxes and cumulative boundary/reaction terms, species-by-species; record accepted times, time-step sequence, nonlinear iterations/convergence, and termination. Fortran `SOLUTE.OUT` definitions include actual/cumulative top and bottom flux, cumulative zero-/first-order removal, and nonequilibrium transfer (`sum(cvNEql)`) (manual Table 13.3, printed p. 230; PDF p. 238). `RUN_INF.OUT` provides `dt`, `IterC`, convergence and maximum Peclet/Courant (Table 13.2, p. 230).
- Independent balance residuals computed from the compared states/fluxes, not only the solver's own reported residual. For each species, report start/end inventory, boundary inflow/outflow, reaction conversion/production, and residual. Concentration boundary exchange inferred internally from closure cannot serve as an independent measurement of that closure; this limitation is already documented for Rust. [M5 accounting limitation](PHASE_5_SOLUTE_EVIDENCE.md#equations-units-signs-and-water-coupling).

### Output sources and units/signs

The manual says `OBS_NODE.OUT` contains transient pressure head, water content, temperature, and solution/sorbed concentrations; `NOD_INF.OUT` provides nodal fields at print times; `BALANCE.OUT` reports subregion inventories/fluxes and solute mass errors (Chapter 13, printed pp. 227–228; PDF pp. 235–236). `SOLUTE.OUT` provides the time-level flux diagnostics above. These are primary extraction candidates, but the actual staged reference output formats must be parsed and verified against generated output; do not assume this repository already has solute fixture parsers.

Fortran manual notation gives dissolved concentration in `[M L^-3]`, sorbed concentration in `[M M^-1]` (mass per soil mass), bulk density in `[M L^-3]`, integrated solute amount in `[M L^-2]`, and flux in `[M L^-2 T^-1]`; Example 3 uses `cm`, `hour`, and its table marks several concentrations dimensionless for the normalized analytical case. Always record concrete unit labels for each fixture, since dimensional labels alone do not settle the basis (e.g. mmolc/L versus mass/volume). Fortran `SOLUTE.OUT` signs are inflow/outflow `+/-` at both top and bottom; Rust's explicit total-solute boundary-flux inputs are positive inward at either endpoint, while water-face flux uses increasing mesh-coordinate sign. Convert signs at the comparison adapter and preserve raw values. [Manual Tables 13.3/13.5](../../planning/reference/HYDRUS1D-4.08.pdf) and [Rust sign contract](PHASE_5_SOLUTE_EVIDENCE.md#equations-units-signs-and-water-coupling).

Potential data hazards to check during parser implementation: Fortran output can be rounded formatted text, multiple species have separate `SOLUTE.OUT` files, records may be emitted at different output levels, and the exact print schedule may not coincide with every accepted internal time step. Compare only common time/space coordinates or interpolate under a documented procedure; preserve raw output and parser tests.

## Paired comparison and oracle protocol

1. **Freeze scope and case provenance.** Record case source/page, whether values were transcribed, independently derived, or recovered, omitted/derived inputs, model mapping, units, mesh, and review. A plotted observation curve is experimental evidence, not an executable expected-output file.
2. **Freeze the reference.** Use the repository's staging/build path and manifest. Record archive/source hashes, patch hash, Fortran compiler/version/flags and precision behavior, executable hash, OS/architecture, exact command, timeout, input/output hashes, stdout/stderr, warnings, exit/completion checks, and isolated run path. Keep the checked-in source immutable. Existing 4.08-or-derivative lineage and unresolved release identity must remain explicit; a pass establishes parity to this pinned snapshot/build only, not general HYDRUS release compatibility. [Source audit](SOURCE_AUDIT.md#provenance), [harness](../../reference/fortran_reference/README.md#generated-paths), [Phase 0 limits](PHASE_0_REFERENCE_EVIDENCE.md#limitations).
3. **Run identical inputs.** Preserve exact deck and produce a canonical normalized fixture description for Rust. Assert both outputs' units, species order, mesh coordinates, times, boundaries, water snapshots, and process switches match before numeric comparison. Where Fortran parser/driver cannot isolate solute from coupled water integration, label the comparison as coupled and record both water and solute differences.
4. **Validate observations independently.** Parse profiles, `SOLUTE.OUT`, `BALANCE.OUT`, and `RUN_INF.OUT` with fixture-specific schema checks. Independently recompute storage/inventory from printed state where available, and recompute flux/reaction closure using the same sign convention. Cross-check Example 3 against the documented analytical CHAIN solution or a separately implemented, reviewed analytical calculation; do not use Rust outputs as their own golden values.
5. **Calibrate, then freeze tolerances.** First characterize Fortran repeatability and compiler/precision sensitivity, then compare discretization/time-step refinement and field-wise Rust/Fortran residual distributions on reviewed cases. Choose per-observable `atol`/`rtol`, normalized profile norms/weights, mass-balance absolute threshold and zero-denominator branch with documented rationale. Record raw vectors and residual summaries; freeze approved tolerances before converting runs into regression gates. A threshold inferred from one case or the prior prompt's `1e-6` candidate is not universal.
6. **Report evidence levels separately.** Keep source-snapshot parity, analytical/physical validation, text-layout compatibility, and release compatibility separate. Passing one does not imply another. A smoke completion proves runner viability only.

## Completion criteria for the proposed catch-up

Mark M5 scientific comparison complete only when:

- At least one in-scope solute fixture has reviewed provenance, complete normalized inputs, units/signs/species order, and hashes; unsupported/manual-to-Rust mismatches are explicitly excluded or resolved.
- A reproducible pinned-Fortran run produces verified solute output records and the same fixture is run through Rust with documented matched water inputs/trajectory and time/space coordinates.
- Extracted dissolved profiles and applicable sorbed/kinetic pools, boundary fluxes/cumulative terms, inventories, and independent per-species balance are compared; Example 3 additionally has an analytical cross-check if that case is selected.
- Field-specific tolerances are justified from repeatability/precision and paired residual evidence, reviewed, stored with the fixture, and exercised as regression acceptance criteria.
- Raw outputs, manifests, parser/comparison results, deviations, and limitations are retained; M5 evidence distinguishes source parity from independent physical validation and release compatibility.

If no qualifying canonical/manual case can be reconstructed, the milestone can still deliver a reviewed, fully specified **derived** comparison fixture, but its provenance must remain labelled derived and its scientific scope limited. It must not upgrade manual reproduction or experimental validation claims.
