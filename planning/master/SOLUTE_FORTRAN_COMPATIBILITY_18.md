# Pinned Fortran solute compatibility contract — Orchestration 18

Status: source audit and contract; **not** an implementation, fixture suite, parity result, scientific validation, or tolerance approval. This contract freezes the behavior targeted by Orchestration 18 within `src_reference/SOLUTE.FOR`. It does not treat the pinned program as scientifically superior or physically validated.

## 1. Authority, provenance, and precision baseline

The numerical authority is the hash-pinned source snapshot in `planning/master/SOURCE_MANIFEST.json`, copied to an isolated build tree and patched with `reference/fortran_reference/0001-gfortran-portability.patch`. The reviewed Phase 0 configuration is GNU Fortran **13.3.0** (recorded build environment: Ubuntu package `13.3.0-6ubuntu2~24.04.1`), Linux x86_64, flags **`-std=legacy -ffixed-line-length-none`**. Patch SHA-256: `622d1ea68285257e98a169f94dec83f3df1c671a9366f651e845806cb8c00d7e`; archive SHA-256: `d0c47cbcb7a298ab16c6e08010bd7ca048d5527ce2f989a749390c0c55e848cf`. The patch affects staged `HYDRUS.FOR` and `TIME.FOR`; the shim supplies remaining legacy entry points in the isolated build. The patch does not change solute algorithms or precision.

With those baseline flags, **default `REAL` is GNU Fortran's default 4-byte real** and `DOUBLE PRECISION` is 8-byte. `SOLUTE.FOR` explicitly declares selected arrays/values double precision (including the tridiagonal coefficients in `Solute`, `MatSet`, and `BanSol`); many other solute variables and arrays are implicit/default real. Therefore calculations are mixed precision, not uniformly double precision. The available sensitivity build added `-fdefault-real-8 -fdefault-double-8`; it is sensitivity evidence only and does not replace the baseline oracle. A tolerance must account for source arithmetic and formatted output separately.

Evidence anchors: `planning/master/PHASE_0_REFERENCE_EVIDENCE.md` §Reference executable; `reference/fortran_reference/SMOKE_RUN.md` §Environment; `planning/master/SCIENTIFIC_COMPARISON_RESEARCH.md` repeatability/precision review; `planning/master/SOLUTE_FORTRAN_FORMULATION_17.md` §Precision conventions.

**Recorded provenance gaps:** baseline compiler/host/flags and hashes are recorded, but there is no cross-compiler/platform matrix; not every expression's effective kind and promotion/rounding sequence has been experimentally enumerated. Existing noncanonical smoke is not a scientific solute baseline. Licensing/redistribution review, exact source release identity, and some legacy shim/runtime behavior remain open. Later fixtures must authenticate the actual source, patch, shim, compiler, flags, executable, inputs, and outputs used; do not infer missing provenance.

## 2. Source call and input path

`HYDRUS.FOR` calls `ChemIn` when chemistry is enabled, then calls `Solute` from the main time loop (`HYDRUS.FOR:271–277, 496–517`; `INPUT.FOR:1289–1421`; `SOLUTE.FOR:6–232`). `ChemIn` reads `epsi`, upstream/artificial-dispersion and temperature flags, nonlinear iteration controls, species/material coefficients, optional temperature and moisture blocks, endpoint codes/concentrations, and pulse end. It derives `lEquil`, `lMobIm`, and `lLinear` from parameters. In particular, `lEquil` becomes false if any material has `Fraction < 1`, immobile water content is positive, or bacteria is enabled; `lMobIm(M)` is set for positive immobile water only when bacteria is off; zero bulk density is rejected for non-equilibrium configuration (`INPUT.FOR:1332–1339`).

The source loops species in ascending order `jS=1..NS`, then nonlinear iterations and two assembly levels (`Level=1..2`); each active level calls `Coeff`, then `MatSet`; `BanSol` follows both levels. It clips negative solved concentration to zero and converts double solution `F(i)` to default real using `sngl`. Nonlinear convergence's `lConv=.false.` assignment is commented out, so the present source does not actually set nonconvergence through that test. Species `jS>1` receives source terms from the previous species. Source arrays are Fortran one-based and native coordinate/profile ordering is top/inlet first; the established verification convention maps native `x=-s` to canonical `s` increasing inlet-to-outlet, reversing node arrays and mapping row `(B,D,E;F)` to physical `(E,D,B;F)`.

### Combination rules

Treat input flags as separate axes unless the source couples them. In particular, `lUpW`/`lArtD`, temperature, tortuosity, endpoint codes, and species count are separately represented; do not infer exclusivity from labels. `lBact` forces `lEquil=false` and disables `lMobIm` assignment; `iDualPor>0` also sets `lEquil=false`; positive immobile water without bacteria sets `lMobIm`. `lBact` and multi-species chain hit an explicit interactive stop path. `lDualNEq` uses pools/update logic whose active updater call is commented. Nonlinear and moisture-dependent equations have source code but are not activated by audited input/caller paths as described above. The normalizer must validate source-supported constraints before execution and distinguish invalid, unsupported, and merely untested combinations; never silently substitute a nearby mode.

## 4. Normalized one-step request and state contract

The request is versioned, canonical UTF-8 JSON with unique keys, finite numbers, explicit units, explicit availability reasons for nulls, ordered species, increasing canonical coordinates/time, and SHA-256 hashes of raw source/input bytes. Its detailed wire schema will be finalized by the adapter task against this semantic contract; any schema change returns to orchestration review. Do not feed Fortran output back as an input.

Each step request supplies: source/build identity; fixture identity/provenance; `t`, `dt`, pulse/boundary schedule and `epsi`; native-to-canonical orientation; node coordinates and material IDs; old/new `theta`, saturation, velocity/face-flow inputs and any immobile/dual-domain histories; temperature history; ordered species and all per-material/species `ChPar`, `TDep`, tortuosity, upstream/artificial dispersion, Pe threshold, moisture flags/data, bacteria/filtration/blocking/deposition selectors; equilibrium/linearity and dual-domain switches; boundary codes and per-species concentration/atmosphere fields; dissolved initial/accepted concentrations, `Sorb`/`Sorb2`/other source pools, sinks, and prior-species state; conversion factors needed by `Deposit`. All required fields must be explicit or use a documented source default; no missing array defaults to zero by convenience.

Canonical units are carried with each fixture and field. For existing verified Example 3 mapping: cm, hour, dimensionless normalized concentration, bulk density g/cm³, Darcy flux cm/hour, dispersion cm²/hour, Kd cm³/g; sorbed concentration/mass has its separately declared compatible basis. The source `Deposit` routine documents grain/bacteria diameter as meters, q as length/time, temperature Celsius, and internally converts using `xConv/tConv`; normalized requests must preserve its exact inputs/conversion factors, not relabel all quantities into an assumed unit system. Water content/fraction/flags are dimensionless; decay/transfer rates carry inverse-time units; coordinates and boundary concentration are per explicit case declaration.

Indexing contract: source species order is 1-based `jS`; material and node indices are 1-based; species blocks use offset `(jS-1)*16`. Canonical node order is increasing flow distance inlet-to-outlet; record explicit source-index permutation. Face/velocity orientation and sign conventions are explicit, not guessed from field names.

## 5. Trace checkpoints and outputs

Capture every checkpoint available from the unmodified algorithm, without changing source solely to obtain instrumentation in this contract:

1. Validated normalized request, source/build/input hashes, flags, array shapes, and native↔canonical permutation.
2. Per species/step/level: incoming concentration and pools; water, temperature, material, and velocity inputs; active branch identifiers.
3. Per node: temperature-adjusted material/species coefficients; liquid/gas/immobile water; `Retard`, `Disp`, `TauW/TauG`, `g0/g1/q0/q1`, `vCorr`, `wc`, Pe/Courant and timestep bound.
4. For each active `MatSet` level: lower/diagonal/upper/RHS and endpoint row/flux terms in native and canonical orientation; preserve double coefficient arrays and any conversion at solve/state boundary.
5. Post-`BanSol` solution before clamp/cast, then after source `sngl`, nonnegative clamp, tiny-value zeroing, and accepted concentration/pool update.
6. `MassTran` per-species cumulative/instantaneous source quantities and endpoint flux accounting at the actual active call point; iteration/termination diagnostics and warnings.

Normalized outputs include all mapped concentration profiles and source state pools at initial and accepted times; endpoint values/fluxes; water/temperature/density external input histories with provenance; dispersion/retardation and diagnostics; per-species integrated transfer/accounting fields returned or printed by the source; iteration/step status; warning and availability records. Preserve `Conc`, `Sorb`, `Sorb2`, cumulative transfer fields, and independent balance terms as distinct quantities. An unavailable source quantity is `null` with reason, not zero or a residual-derived substitute. Printed-file parsing must preserve source format and quantization interval; e.g., verification sources record concentration/sorbed e12.4, coordinates f10.4, theta f6.4, solute flux e13.5, subject to actual selected output format declarations.

## 6. Comparison and tolerance policy

Compare request identity and discrete fields exactly: schema, units, hashes, branch switches, ordered species/material map, source indices/permutation, endpoint codes/orientation, accepted time schedule, iteration/termination status, warnings/completion, output schema, and availability reasons. Compare arrays only after coordinate/time/species identity is validated. Require exact equality for integer/boolean/state-transition fields and schedule records; compare floating fields using paired source precision intervals when values come from formatted output.

For each continuous field define `abs(a-b) <= atol_field + rtol_field * max(abs(a),abs(b))`, with units, denominator/normalization, and zero/near-zero behavior recorded. Also report maximum absolute/relative difference and suitable L1/L2/RMS metrics for fields/profiles, without combining species or unlike units. Calibrate each field from repeated baseline runs, observed output last-place intervals, compiler/default-kind semantics, and identified promoted-real sensitivity; propagate coordinate/input quantization as relevant. The old `1e-6` candidate is not universal. Existing comparator thresholds are diagnostic/unassigned. No tolerance is approved by this contract; unresolved/calibration-failing fields stay blockers rather than being widened to pass. Exact printed text identity is not numerical parity, and parity is not physical or continuum validation.

## 7. Fixture provenance and coverage gate

Each mode/valid-interaction fixture must state whether recovered from a canonical/manual deck, directly supplied, or independently derived; cite every numeric value and hash input bytes. Record source/build/patch/shim/compiler/flags/executable identities, invocation, external histories, output inventory/completion, and artifact hashes in immutable isolated run manifests. Do not call a derived input a recovered manual reproduction. `reference/fortran_reference/solute/example3/CASE.json` is an executable **derived** Example 3 motivated by manual §11.3, not the recovered deck: original deck, manual grid/domain, and numeric CHAIN arrays are absent; the finite 250 cm/1001 node grid and several hydraulic/time inputs are derived; current declared tolerances are absent. It is useful provenance/context, not blanket branch coverage.

Coverage is a matrix over every active branch and source-supported combination, with a discriminating fixture or explicit source-backed blocker for each row. Cover independent switches one at a time and supported interactions where source couples behavior (including direction × endpoint, transport weighting × artificial dispersion, material/species variation, temperature/property modes, and process-state branches). Keep an explicit inventory of source-present inactive/unreachable routines and why inactive. A mode with no callable input mapping cannot be silently declared covered.

**Default gate:** retain existing Rust conservative FV/BE behavior as an explicitly selectable solver. The distinct source-compatible backend may become the default only after every active/callable mode and required supported interaction in this contract has authenticated fixture evidence, all mapped inputs/checkpoints/outputs meet reviewed exact or calibrated field-specific criteria, no in-scope blocker/unmapped active branch remains, and the all-mode parity report is accepted (task 18.10.1). Until then FV/BE remains current default and its equations/tests remain intact. Neither backend selection nor parity changes scientific superiority claims.
